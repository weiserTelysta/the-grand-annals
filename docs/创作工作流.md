# 《龙冠枯荣》创作工作流

这个 `docs` 文件夹是一座独立的 Obsidian 内容库。网站的颜色、排版、组件和自动生成逻辑都位于仓库外层的 `overrides` 与 `tools`，日常创作不需要接触它们。

## 新建公开条目

1. 在 `zh` 下进入最符合内容类型的文件夹，例如人物放在 `zh/星辰微光`，地理放在 `zh/山河地理`。
2. 新建与条目同名的 Markdown 文件。
3. 打开命令面板，执行“模板：插入模板”，选择对应的公开条目模板。
4. 填写 `description`。它必须是一句能让陌生读者理解条目价值的话。
5. 正文只使用标题、段落、列表、引用、图片与相对 Markdown 链接；不要写 HTML 或 `{: .class }` 之类的网站样式标记。
6. 在 `related` 中填写 2～5 个真正有助于继续阅读的条目，例如 `"[[长域]]"`。不需要手写相关条目卡片。

新条目位于 `zh` 后会自动进入条目索引，但公开侧栏是经过整理的读者目录，不会把任意文件夹原样暴露出来。需要进入侧栏的重要条目，在内容成熟后统一加入 `zh/.nav.yml`；日常写作仍不需要修改 `mkdocs.yml` 或索引页。`zh` 是网站发布边界，因此不要在公开条目中填写 `status: 公开`；不准备放上网站的内容可放在 `weiser`。

## 选择相关条目

`related` 是作者为读者精选的延伸阅读，不是自动反向链接。按以下顺序选择：

1. 理解本页所需的前置概念；
2. 直接相关的人物、地区、组织或事件；
3. 当前内容的因果、后续或主题延伸；
4. 最适合继续阅读的下一页。

不要仅仅因为标签相同就建立关系，也不要求每一对关系双向出现。首页、分类页和索引页可以没有 `related`。

## 插入图片

Obsidian 会把新粘贴的附件统一放进 `zh/assets/uploads`。这个目录位于公开边界内，因此只放准备公开的图片；非发布草稿所用的原图继续放在 `weiser` 下，不要粘贴到公开附件目录。

发布前请为图片写清楚替代文字，例如 `![特莉丝塔的全身立绘](相对路径.webp)`。验证器会检查缺失图片、空替代文字和不应发布的原始超大图片。常用展示图应先转换为 WebP；PNG 原稿不直接进入网页。

## 新建非发布草稿

在 `weiser` 下新建文件并插入“私人草稿”模板。网站只构建 `zh`，因此这些文件不会出现在网站中；但当前 GitHub 仓库是公开仓库，已提交的 `weiser` 文件仍可在仓库中被看到。真正需要保密的草稿必须放在本仓库之外的独立 Obsidian 库。

## 内容检查

打开 `内容工作台.base`，可以查看公开内容、缺少简介、知识条目缺少关联、非发布草稿和最近修改。发布前回到仓库根目录执行：

```powershell
.\.venv\Scripts\python.exe tools\validate_content.py
.\.venv\Scripts\python.exe -m mkdocs build --strict --clean --config-file mkdocs.yml
.\.venv\Scripts\python.exe tools\validate_site.py site
```

构建失败时先看终端指出的文件。最常见的问题是缺少 `description`、`related` 指向不存在的条目，或 Markdown 链接路径错误。
